# Prediction registered 2026-09-15, BEFORE v7 sidecars exist

## The defect under test

`context/03-requirements.md` R28.1 (committed today) states:

> "the carrier MUST hold **both** the ClickThrough URL and its associated
> click-tracking URL(s). ... a ClickThrough present without its
> click-tracking is a violation the document shows."

The spec's own syntax table (v6.1 §5.6.1, regenerated in every build)
declares:

> `@clickThroughUrl`  Required: yes
> `@clickTrackingUrl` Required: **no**

A rule that mandates a field the same document declares optional. Both
halves live inside the artefact the validators read; no external context
is needed to see it.

## The prediction

**If** `output-analysis/v7-spec-validation.md` or
`output-analysis/v7-dash-conformance-audit.md` flags this contradiction
→ the validators cover intra-document rule-vs-syntax conflicts, and the
pipeline caught a defect a human introduced the same day.

**If neither flags it** → this is a coverage gap in the validators, and
it is worth as much as the finding itself: it says the sidecars do not
cross-check a normative criterion against the syntax table the same
document defines.

Either outcome is to be reported explicitly. Silence is not a result.

## What must NOT happen while this is under test

`context/` is not edited until the build finishes. Editing it mid-run
changes the input underneath the build and destroys the attribution
between input and output.

## Addendum, same day, before the result

The corrected R28.1 text (co-location instead of presence) was reviewed
and approved while this build was running. **It is deliberately NOT
applied until the build ends.**

The reason is the experiment itself: v7 must be generated from the
defective text. Fixing the input mid-run would destroy the only free
datum this build can produce — whether the validators catch a normative
criterion that contradicts the syntax table in the same document.

A deferred fix here is not an oversight. It is the control.
