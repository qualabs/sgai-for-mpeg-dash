### A-2 — R20.1's reading of the base failure condition (audit K-36)
- **Context passage:** 03:1668-1674 R20.1: *"A resolution document that carries candidates is not a failed execution, whatever the Player then does with them. … The base specification's condition is media availability after the merge, not renderability on a device; this specification does not extend it there."* Same criterion, 03:1660-1661: *"For the linear family this is adopted unchanged from the base specification."*
- **The base:** §5.16.2.2.6: *"Execution fails if at least one of the conditions below is true at PRTA:"* … *"The playback of the alternative presentation cannot start. The reasons for this include (but are not limited to) the following (at time PRTA):"* followed by *"Alternative MPD is unavailable or invalid."*, *"Alternative MPD is a List MPD, and merge process resulted in no available media."* and *"Media playback is impossible due to missing media or initialization segments."*
- **Readings:** (a) R20.1's: the base condition is media availability after the merge, so a List MPD whose candidates the device cannot render is not a failed execution; (b) the base's: the governing condition is that playback *"cannot start"*, its list of reasons is open, and a List MPD the device can render none of cannot start — a failed execution, after which *"steps a-c above are repeated for next events in QE"* (§5.16.2.2.5).
- **Spec assumed:** (a), faithfully to R20.1: PLY-41 L1119-1122, §7.12 path 4 L3354-3356, and the §4.8.3 bullet L1933-1937 that v12.2's T3 added (*"The base condition is media availability after the merge (DASH §5.16.2.2.6), not renderability on a device"*), which files it under *"look like departures and are not"*. That T3 rested on the *"merge process"* item alone and did not weigh *"(but are not limited to)"*; the base text refutes the premise it cited.
- **Resolution:** R1.5 (03:165-172, *"the base specification's answer takes precedence: this specification adopts it and cites it"*), R20.1's own *"adopted unchanged"* for the linear family, ADR 0006 (*"Where MPEG-DASH already answers a runtime question, this specification adopts its answer and cites it"*) and ADR 0011's criterion (*"a Player implementing this specification and a Player implementing the base standard should not diverge on the same manifest"*) all pick (b) for the linear family. ADR 0011's last consequence (*"One adjacent case is deliberately not decided"*) leaves the case open on the same factual premise the base refutes. The non-linear families are outside the base (R20.1 03:1661-1666), so R20.1's rule stands there.
- **Routing:** 5.d (P-5), with K-36.
