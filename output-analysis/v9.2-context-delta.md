| 1 | 4de39f3 | R35 (incl. summary-table row) | added | needs-structure | Carrying it means choosing a carrier against one the base standard already has, and the two conflict. DASH §5.16.5.2 defines `@skipAfter` on the alternative-MPD events: *"describes an offset in time (in fractional seconds) from the beginning of the alternative presentation till the moment the rest of that presentation may be skipped by the application in response to a user action"*, and *"Zero duration implies that skipping is allowed everywhere … Default value is PT0S"*. DASH Annex K.3.8, Table K.9 gives the same key per service-description scope (`PlaybackRestrictions@skipAfter`, per `ListMPD` Period in the example of G.29.2). Conflicts: (a) the base default is "skippable everywhere", while R35.1 makes an undeclared slot non-dismissible, and 06's reuse rule requires the base default along with the name; (b) the base scopes the key to one presentation or one Period, while R35.4 makes the unit the whole slot; (c) R35 puts the declaration in the resolution document, the APS's, while the event attribute is the Publisher's; (d) for the linear family it extends the `ListMPD` that §1.1 says is reused verbatim. The spec already cites `@skipAfter` as the base's user-action pattern (§5.6) and lists it on `<InsertPresentation>` (§5.1.1). The regenerated `context-analysis/dash-gap-analysis.md` reaches the same point (G11, open question 11: *"This is a decision, not a drafting detail"*). Deciding reuse or a new carrier, and changing the linear baseline, is a major's job. |
| 2 | e7336e3 | R36.1 | added | ambiguous-source | R36.1: *"The declaration is optional; a window that does not carry it is resolved when it fires."* `06-naming-and-namespaces.md`, "Naming consistency with baseline DASH": *"the spec MUST reuse the existing baseline construct with all its characteristics — name, default values, permitted value domain, units, semantics."* The existing carrier is the reused base `@earliestResolutionTimeOffset`, whose base default is 60 s (DASH §5.16.5.2: *"The default is 60 seconds in units of timescale"*). Reading A: keep the reused attribute and its default, so a window that declares nothing may be resolved 60 s early, against R36.1. The two readings oblige the Player differently. `context-analysis/dash-gap-analysis.md` G12 flags the same conflict (open question 12) and notes that the base schema declares no default for the attribute while its semantics table gives 60 s. The spec keeps the 60 s default until a human decides. |
| 3 | 5244a0b | R38.1 | added | ambiguous-source | R38.1: *"Declaring the allowed layouts on a non-linear slot is OPTIONAL."* The spec makes `@allowedLayouts` required on both non-linear windows, and `context/` does not say what a window with no allowed layouts admits. R5.6 checks options against *"the Publisher-declared allowed layouts on the slot"*, and R38.2 only says *"When the slot declares none, nothing is sent."* Reading A: a window without the declaration admits every token of its own family.
