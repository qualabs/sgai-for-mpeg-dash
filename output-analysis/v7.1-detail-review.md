### Delimiter check called for by the dispatch

Both hold in v7.1, and they are different rules:

- **`@profiles` is comma-separated.** §5.2.2.2 types it as a comma-separated
  list and cites §8.1 of the base specification for it. No example anywhere in
  the document carries a space-separated `@profiles`; all 20 `profiles="…"`
  occurrences carry a single URI, so no delimiter is actually exercised, and
  none is mis-authored.
- **`@allowedLayouts` is whitespace-separated.** All 10 occurrences in the
  examples use a single space, per `context/06-naming-and-namespaces.md`
  ("Preferred encoding patterns": the delimiter is space). §5.1.3.1 and
  §5.1.4.1 both type it as "whitespace-separated list of tokens", which is the
  accurate type-level statement for a `StringVectorType`-shaped attribute and
  is consistent with the `context/06` rule rather than a widening of it.
