## Gaps (4)

### G-1 — VAST behaviours with no place in the resolution document
- **Spec section:** §6.6 L3104-3107 (*"every ad behaviour a VAST-based ADS expresses has a place in the resolution document"*), row L3117 (impression and progress tracking only); §5.5 L2525-2533 (timed callbacks only).
- **What the context is missing:** R11.4 (`../context/03-requirements.md` L232-236) requires covering the behaviours a VAST ADS can express, but names none. Interaction-triggered tracking (`skip`, `close`/`closeLinear`, `mute`, `pause` — including the beacon for an R35 dismissal), `<Icons>` and `<AdVerifications>` have no carrier and no out-of-scope statement.
- **What an implementer does today:** proprietary extension, or drops the beacons.
- **Routing:** 5.b.

### G-2 — R9.3's recorded extension consideration is missing for several constructs
- **Spec section:** §4.8.2, header L1859 (*"Why no base construct could be reused, or extended"*); rows `@onExhausted` L1876, `@family` L1877, `<svta:Ad>` L1868, metadata elements L1873, `@background` L1878, `@duration` L1869.

- **What an implementer does today:** nothing — a document defect, visible to WG reviewers.
- **Routing:** 5.b (authoring per row).

### G-3 — What the required cap of a pause window bounds
- **Spec section:** §4.5.4 table L995 (*"one pass through the candidates of one resolution document"*), PLY-24 L997-998, §5.1.4 L2145.
- **What the context is missing:** R4 prose says *"A pause slot has no declared duration for a cap to bound"* (`../context/03-requirements.md` L378-383), while R4.1 (L393-395) requires a cap on every pause slot and R31.2 (L495-499) says it bounds neither. Interaction with `@onExhausted="repeat"` / `request-again` is unstated.
- **What an implementer does today:** follows the spec's "one pass" reading, which is not in `context/`.
- **Routing:** 5.c (D-1).

### G-4 — The spec's open questions are not recorded as open in `context/`

- **What the context is missing:** the "Deliberately open" table (`../context/03-requirements.md` L2297-2318) is empty — *"no silence in this specification has been declared deliberate yet."* Every §8.13 item is therefore an unchosen silence.

## Edge cases (3)

### EC-1 — `@allowedLayouts` naming a token of the other family
- **Trigger:** an overlay window with `allowedLayouts="overlay pause-fullscreen"`.
- **Why it matters:** the APS may conformantly return a `pause-fullscreen` option (it is in the received set, APS-9 L817-819; the set is forwarded unchanged, §5.8.3 L2697), and the Player refuses it (§3.4.3 L557-560, PLY-18 L952-954). The Publisher side is indicative only (PUB-4 L671-672); the schema admits any token on either window (L2877, L2891).
- **Responsible actor:** Publisher / APS; `context/` is silent on whether such a declaration conforms (R12.2 L595-606, R38.1 L1211-1218).
- **Routing:** 5.b.

### EC-2 — Base condition cited for a resolution that carries no candidates
- **Trigger:** a resolution document that parses and carries no candidates.
- **Why it matters:** PLY-39 row 4 (L1094) maps it to *"The playback of the alternative presentation cannot start"*, with the List MPD condition only as a "closest analogue"; R20.1 maps it to *"Alternative MPD is a List MPD, and merge process resulted in no available media"*. The treat-alike obligation holds; the grounding differs from the requirement's own citation.
- **Responsible actor:** Player; `context/` and the spec cite different base clauses.
- **Routing:** 5.b.

### EC-3 — PUB-13 for a pause window declared inside an alternative presentation
- **Trigger:** an alternative presentation's MPD carries a pause window; the main MPD requests the `PlayList` metric.
- **Why it matters:** §8.13 item 6 (L3661-3668) leaves open whether the main MPD's request covers it. R33.4 reads literally as binding whichever MPD carries the window.
- **Responsible actor:** Publisher.
- **Routing:** 5.b.
