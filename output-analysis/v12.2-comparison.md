## Per-category notes

- **The two columns do not count the same objects.** The dist sidecar
  predates the per-criterion coverage map: it indexes 30 requirements with
  `full` / `partial` / `gap` / `governance`, and v12.2 indexes 211 units
  (164 criteria, 30 prose obligations, 17 use cases). `full` is counted as
  `met`, and `contradicted` and `force-lost` as `0`, because the four old
  statuses already exhaust its 30 rows. Every coverage Δ, the +189 on `met`
  and the -3 on `governance` included, measures the change of unit and not a
  change in the spec.
- **The candidate also carries requirements the published build does not**
  (the R2.2 delta, and whatever else `context/` gained since v7.2), so the
  comparison is not like-for-like on content either. The counts were taken
  as the sidecars state them regardless.
- **Ambiguities more than doubled (7 → 16)** while Gaps and Edge cases fell.
  Part of the rise is consistent with a finer walk (A-15 counts criteria
  with no RFC 2119 keyword; A-16 is a build-label error), but this report
  does not read the spec and cannot apportion it.
- **One criterion is contradicted** where dist had none; the audit's
  single Non-conforming item (K-36, PLY-41 on the linear family) is
  described there as unchanged since v12.
- **The grounding differs.** The dist validation is tagged
  `GROUNDED_BY=spec-only`; the v12.2 validation consulted the primary copy
  of the base standard.
