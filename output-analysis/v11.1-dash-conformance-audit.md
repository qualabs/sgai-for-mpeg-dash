# DASH conformance audit — v11.1 (2026-09-26)

**Audit target**: `../output/v11.1-sgai-spec.md`.
**Reference**: the edition declared in
`../context/00-normative-base.md` (ISO/IEC 23009-1:2026, Sixth edition).
`bin/check-normative-base.py` confirmed the cover tokens and the `sha256` of
the primary copy on disk before the audit started. Schema: `DASH-MPD.xsd`
(with `DASH-MPD-UP.xsd`) from the edition's schema package
`DASHSchema-6th-Ed.zip`, at the URL the base gives in Annex B.
**Method**: inventory + clause searches against the primary copy + schema
validation of every example + base-rule checks on every complete MPD +
per-construct verdict.

## Scope

Whether each construct v11.1 introduces, reuses or modifies is valid under the
base specification: the MPD schema, the extension-point rules (§5.2.1), the
Event and Event Stream rules (§5.10), the Alternative MPD model (§5.16), the
Linked Period merge (§5.3.2.6), the profile restrictions (§8.1, §8.4, §8.13,
§8.14, §8.15) and the semantics of inherited base attributes. Design quality
is out of scope.

## Method summary

- **Inventory** built from §1.3–§1.4, §2.1, §3.4, §4.5, §4.7, §4.8, §5.0–§5.10,
  §8.13 and the complete documents of Annexes A–Q.
- **Quotation check.** 102 italic quotations from the base were searched in a
  whitespace-flattened extraction of the primary copy. 100 matched verbatim.
  The other two were confirmed by reading the source: the Table 63
  `@skipAfter` row is split across table columns, and *"a key use case"*
  differs from the source only by the capital letter. Controls: *"At least one
  Adaptation Set shall be present in each Period"* was found; the same
  sentence with one word changed was not.
- **Clause-number check.** Each quotation was located in the extraction and its
  enclosing clause compared with the clause cited next to it. No quotation is
  attributed to a clause about a different subject. Where the first match
  fell elsewhere (*"The elements and attributes listed in subclause 5.2.3.2
  may be ignored"* first appears in §8.2.2), the cited clause (§8.4.2, §8.3.2)
  was read and contains it.

  layout token outside the enumeration, an `svta:Ad` with no option, an
  unknown `@family`, an `svta:Ad` without `@duration`, a bad `@dismissAfter`,
  a non-integer `@durationCap` inside an MPD `Event` (the `lax` path), an

- **Nesting check (DR-3).** No DASH-namespace element sits inside an `svta`

## Base-standard findings (highlights)

- **Extension points** (schema read directly): `MPDtype`, `PeriodType`, `EventType`,
  `AlternativeMPDEventType` admit foreign elements and attributes;
  `EventStreamType` admits foreign elements only; `ImportedMpdType` foreign
  attributes only. DR-2 is exact. `PeriodType` and `AlternativeMPDEventType`
  carry `SupplementalProperty` only; `EventStreamType` carries both descriptors
  in the schema, although Table 43 lists only `SupplementalProperty` (a base
  inconsistency that does not affect any construct, since none uses a
  descriptor).
- **List profile**: *"The ISO-BMFF List profile is an extension of the ISO-BMFF
  CMAF Profile"* (§8.14), and a Media Presentation conforms to a profile only if
  *"There is at least one Representation in each Period in the profile-specific
  MPD for ProfA"* (§8.1). This is what makes C30 marginal.
- **Skip default**: Table 63: *"Zero duration implies that skipping is allowed
  everywhere … Default value is PT0S."* The base's own List MPD example
  (Annex G.29.2) comments a Period with no restriction as *"no playback
  restrictions, the user is permitted to skip this ad"*. This is what makes C26
  marginal.
- **Failure conditions are open-ended**: execution fails when *"The playback of
  the alternative presentation cannot start. The reasons for this include (but
  are not limited to) the following"* (§5.16.2.2.6). This is what makes C24
  marginal.

## Non-conforming items detail

None. No construct violates an explicit rule of the base specification: every
example validates, every stripped MPD validates, and every checked profile and
event rule holds.

## Marginal items detail

### C5 — URN form of the SGAI identifiers

- **Ambiguity.** The four identifiers use the NID `svta`, which is not among the
  formal URN namespaces of the IANA registry (fetched 2026-09-26; control:
  `mpeg`, `dvb`, `iso` present). The base only requires URN *syntax* for scheme
  identifiers (Table 43) and a *"URN or tag URI"* for request types (Table I.4),
  so no base rule is broken; but an unregistered NID is not a valid URN under
  RFC 8141, and the base itself holds its own profile URNs to *"shall conform
  to IETF RFC 8141"* (§8.1).
- **Suggested clarification.** Either state that SVTA intends to register the
  NID (or already uses it by arrangement), or mint the identifiers as tag URIs
  (`tag:svta.org,2026:…`), which Table I.4 names explicitly.

### C16 — Window span at a Period boundary

- **Ambiguity.** §5.1.3 defines the window's span as `Event@presentationTime`
  plus `Event@duration` on *"the timeline of the presentation whose MPD
  declares the window"*. Under §5.10.2.1 an Event ends at the end of its
  Period whatever its duration. The spec does not say whether a window whose
  span crosses a Period boundary ends at the boundary or continues. No example
  crosses one.
- **Suggested clarification.** One sentence in §5.1.3: the span ends at the end
  of the Period (§5.10.2.1), and a window continuing into the next Period is a
  second window in that Period.

### C24 — PLY-41 applied to the linear family

- **Ambiguity.** PLY-41 says a resolution document carrying candidates is never
  a failed execution, and a candidate the device cannot render ends at the
  primary content, *"not at the next window"*. For a List MPD, the base treats
  *"The playback of the alternative presentation cannot start"* as a failed
  execution with an open list of reasons, and a failed execution falls through
  to the next event in the queue (§5.16.2.2.5 step 2 d). A List MPD whose only
  candidate the device cannot decode is, under the base, a failed execution
  that reaches the next linear event; under PLY-41 it is not.
- **Suggested clarification.** Restrict PLY-41 to `<svta:OverlayList>`, or record
  it in §4.8.3 as a departure for the linear family.

### C25 — Drop-before-play of a List MPD Period (PLY-35)

- **Ambiguity.** The base trims (*"For insertion events, APDA = min(APD,
  APDmax)"*, Table 57); it does not skip a Period whose declared duration would
  overrun the cap. §4.5.5 calls this *"this specification's permission"*, but
  §4.8.3 opens with *"One decision departs from what the base specification
  would do with a base construct"* and lists only supersede. The two sections
  disagree about how many departures exist.
- **Suggested clarification.** List PLY-35 (applied to List MPDs) in §4.8.3, or
  restrict it to the non-linear families.

### C26 — Linear dismissal when `@skipAfter` is absent

- **Ambiguity.** §5.2.4 item 4 and PLY-78 make an inherited linear slot
  non-dismissible when neither `@skipAfter` nor `PlaybackRestrictions@skipAfter`
  is written and the List MPD carries no `@svta:dismissAfter` (or carries
  `never`). The base gives the absent attribute a meaning: *"Default value is
  PT0S"* and *"Zero duration implies that skipping is allowed everywhere"*
  (Table 63), and its own example reads a Period with no restriction as *"the
  user is permitted to skip this ad"* (Annex G.29.2). Skipping is a permission
  to the application, so a Player that does not offer it breaks no `shall`;
  but the spec overrides the default of a base attribute on a base construct,
  §4.8.3 lists it as not being a departure, and the last sentence of PLY-78
  (*"A Player of this specification and a base Player treat the same linear
  event the same way"*) does not hold for an event without `@skipAfter`.
- **Suggested clarification.** Record it in §4.8.3 as a departure (narrowing a
  base permission on inherited events), and drop or qualify the last sentence
  of PLY-78.

### C30 — Empty linear resolution

- **Ambiguity.** A `PT0S` Period with no Adaptation Set is valid under Table 4
  and the resulting MPD is conforming. Under the List profile, which extends the
  CMAF profile, *"If the Subset element is not present, the Period contains
  exactly one CMAF Presentation"* (§8.12.4.4) and a conforming Media
  Presentation needs *"at least one Representation in each Period"* (§8.1).
  The empty List MPD is therefore a conforming MPD and not a conforming Media
  Presentation under its declared profile. The base's own failure condition
  (*"Alternative MPD is a List MPD, and merge process resulted in no available
  media"*, §5.16.2.2.6) presupposes such documents exist. The spec states this
  itself in §8.13 item 9.
- **Suggested clarification.** None needed beyond §8.13 item 9; confirm with the
  base editors when the other open questions go.

## Open questions surfaced

1. **An event starting exactly at the Period end** (C33). The base says events
   *"shall terminate at the end of a Period"* (§5.10.2.1) and does not say
   whether an event whose start equals the end is dispatched. The base's own
   Annex G.29.2 example places one there, so the spec follows base practice.
   Searched: "terminate at the end of a Period", "spill over", "end of the
   Period" (14 hits, none on this case).
2. **Advanced Linear profile** (§4.8.5, §8.13 item 1). Not used by any annex;
   the text does not settle whether an SGAI stream makes a Period
   non-conforming. Confirmed that the base's `example_K6.4.mpd` (Advanced
   Linear) carries an `EventStream` of `urn:mpeg:dash:event:service-description:2024`,
   a scheme §8.13.2.2 does not name.
3. **An emptied `@includeInRequests`** (C4). After a legacy client drops the
   URN, the attribute value is empty; the base does not say whether that means
   no request type or the default `"segment"`. Either reading is harmless here:
   the concatenation end point for segment requests is the Representation
   hierarchy (Annex I.3.4.3), which does not pass through an `EventStream`.

**Other observations (citation and example precision, not constructs):**

- **E1.** §1.3 (line 156) cites `DASH §4.8.9`, which does not exist in the
  edition (clause 4 ends at §4.7). Already listed in the spec's refinement
  gaps (#14).
- **E2.** §4.8.2 (`<svta:Tracking>` row) says the base declares `EventStream`
  *"only as a local element of `Period`, `AdaptationSet` and their kin"*. In
  the schema `EventStream` is declared only in `PeriodType`; Adaptation Sets
  and Representations carry `InbandEventStream` (same type, other name). The
  conclusion is unaffected.
- **E3.** The §5.8.1 example is a complete `MPD` whose `Period` has no
