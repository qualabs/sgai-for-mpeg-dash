**Role of this run.** This is the baseline validation for an incremental build. v9.1 is a minor refinement of v9, built 2026-09-18. `context/` has moved since then: R35, R36.4–R36.6, R38 and R39 were added or extended, the layout tokens changed (ADR 0014), and ADR 0015 settled R4.10. **What this walk covered.** `bin/check-promotable.py --population` lists 201 units: 154 conformance criteria, 31 prose obligations and 16 use cases. All 201 were walked, and each has exactly one row in §4, under the id the script prints and in the order it prints them. The units were walked in seven disjoint slices, each by an independent reviewer who read only the spec, `context/` and `context-analysis/`. The slices were then merged. At the merge, one convention was harmonised across slices: a bullet under the §4.2 / §4.4 conformance lead-ins that states a `context/` MUST without a keyword is `force-lost` (validate-spec §4.2), not `met`. This turned R15.2 and R30.1 from `met` into `force-lost`. The question behind the convention is A-1.

## Gaps (8)

**G-1 — Viewer dismissal (R35) and resolution lifetime (R36.4–R36.6) are absent.**
- Sections that need them: §5.2.2 (resolution-document attributes), §4.4 (APS), §4.5 (Player).
- `context/` specifies the behaviour in full. Nothing is missing on the context side, and the spec predates it. A search for `dismiss` in the spec finds only dismissal on resume and the automatic dismissal at `@maxDuration`. §8.8 says only that *"no threshold is fixed here"* on the staleness of a speculatively obtained document.
- Implementer today: dismissal is proprietary or unavailable, and a held pause document is used however stale it is. → 5.b.

**G-2 — Allowed layouts: required in the spec, optional in `context/`, and never forwarded to the APS (R38, UC-15, R29.8).**
- Sections: §5.1.3 / §5.1.4 (L1887, L1961 mark `@allowedLayouts` required), §5.8 (reserved parameters), §4.4, §4.5.2 L775.
- The spec contradicts R38.1 (optional) and R38.4, because §4.5.2 L775 releases the APS from the Publisher's declarations. It has no carrier for R38.2 / R38.3 (forwarding): `sgaiAllowedLayouts` 0 hits, `R38` 0 hits, against 54 hits for `allowedLayouts`. The Player's own pre-render check (R38.5) is met.
- Implementer today: the APS spends options the Player throws away, and on D2 an opportunity that could have been filled goes empty. Each APS guesses a proprietary parameter. `context/` does not say what the Player's check admits when the slot declares no set. → 5.b.

**G-3 — `custom` layout (R39, UC-16) absent. The closed layout set now contradicts it.**
- Sections: §3.2 L381-388 / L412-413 and §5.3.3 L2433-2435 declare a closed, IAB-only set (*"accepts nothing outside this list"*). §1.3 L126-128 lists position semantics as out of scope. `custom` 0 hits and `percent` 0 hits, against 35 hits for `pause-partial`.
- Missing: the token, the percent region on the slot, its travel with G-2's carrier, the APS rectangle MUST (R39.4), and the Player's containment check (R39.5).
- Implementer today: a `custom` option fails the exact-token match and is skipped. That happens to be the conformant outcome for a Player that does not support `custom` (R39.1), but no implementation can support the mode. Depends on G-2. → 5.b.

**G-4 — Layout vocabulary has drifted from `context/` (R12.1–R12.3, UC-09, UC-13, UC-15).**
- `context/` (R12 table, ADR 0014) has `squeezeback-l-shape-upper-left` / `-upper-right` and `squeezeback-double-box-background`. The spec (§3.2 L396/L398, §5.3.3) has one orientation-free `squeezeback-l-shape` and `squeezeback-double-box-with-background`.
- Implementer today: a manifest or resolution document that conforms to `context/` fails the spec's exact-token match on every such option. The result is a silent skip.
- Renaming the background token is mechanical. Splitting the L-shape needs a geometry per orientation in §5.3.7.1, which is authoring. → 5.b.

**G-5 — Linear candidates cannot carry the ordered option list that UC-01 / UC-02 and R5.1 give them.**
- Section: §5.2.1 L2056-2059. The linear `ListMPD` is *"not a candidate set the Player selects from"*, with one `<ImportedMPD>` per Period. UC-01 / UC-02 give each linear candidate a video form *"optionally with an image or HTML form as a fallback"*, and R5.1 does not exempt linear.
- Implementer today: sends only a video sub-MPD. An image or HTML linear fallback cannot be expressed.
- Two remedies: narrow `context/` so that R5 covers non-linear only, or give linear slots an option carrier. → 5.b.

**G-6 — R4.10 is settled (ADR 0015, accepted 2026-09-21), but the spec still calls it provisional and does not score it.**
- The phrase "provisional and open with the working group" appears at L583, L854, L1779, L3477, L3733, L3969, L8575 and L8682. It is also listed in §8.12, and T-25 records the rule without scoring it. R4.10's guidance that open-ended advertising is written as a chain of bounded slots appears nowhere.
- Implementer today: may treat the no-cap rule as optional. → 5.b. Removing the status wording is close to a byte-level edit, but the missing chain guidance is authoring.

**G-7 — UC-08's "the overlay candidate doubles as the pause-ad candidate" names a signal nothing defines.**
- `context/04-use-cases.md:886`. `grep -ci doubles` over the spec gives 0, and over `context/*.md` the only hit is that line, so no requirement backs it either. The spec always re-resolves (§H.6 step 6, L6502).
- Implementer today: always resolves, or invents a flag. → 5.c.

**G-8 — R8.1: the new URIs carry no justification.**
- §2.1 L196-198 / §4.8.2. The overlay and pause-trigger scheme URIs and the resolution-document profile URI are introduced with no "why not an existing scheme or profile" statement. §4.8 opens (L1478-1480) by claiming such a justification exists for every construct. The spec itself lists this as Refinement gap #6.
- Missing from `context/`: whether a URI counts as a "construct" under R8.1. → 5.b.

## Edge cases (6)

**EC-1 — The no-cap rule suppresses linear breaks in MPDs that never claimed SGAI (R1.3, R1#p1).**
- Trigger: a Player conformant to this spec plays an ordinary DASH MPD, with no `svta` namespace, whose `<InsertPresentation>` / `<ReplacePresentation>` omits `@maxDuration`.
- Why it matters: §4.5.4 L847-849 (*"the Player MUST present no ads from it"*) applies to every inherited linear element, because linear slots carry no SGAI marker. A break that is valid under the base standard, where absent means unbounded, is silently dropped. The spec admits the divergence at L855.
- Actor: Player. `context/` contradicts itself here rather than being silent: R4.10 mandates the rule, while R4.8 says it changes no construct's semantics. → 5.c.

**EC-2 — A candidate that passes some eligibility checks and fails others (R2.3).**
- Trigger: the options match `@allowedLayouts` and §3.3, but the declared duration exceeds the remaining cap.
- Why: §4.5.2 L771-773 defines only "satisfies them" and "satisfies none". The cap is a MAY drop (L824-826) plus a MUST trim, so "skip" and "render and trim" are both readable.
- Actor: Player. `context/` is silent on how R2.3 composes with R4's MAY. → 5.b.

**EC-3 — The trim sentence is written per candidate, while R4.2 is cumulative.**
- Trigger: a multi-candidate slot where each candidate fits the cap but their cumulative length does not.
- §4.5.4 L828-830 (*"Where an accepted candidate's actual rendered length exceeds the cap"*) does not oblige a trim there. §7.4 L3527 and the §8.2 cap row do, as does R4.2.
- Actor: Player. Two spec sites disagree, and one matches `context/`. → 5.a, **See Actionable TODO T4**.

**EC-4 — A pause that outlives the time-shift buffer (R25#p1, R25.1).**
- Trigger: live content, where the viewer pauses inside a pause window for longer than the buffer depth.
- §4.5.10 L1009-1015 keeps the freeze and clips only the resume point. §7.6 L3575-3577 says the freeze holds *"for the duration of the pause, up to the time-shift buffer"*, which reads as the freeze itself ending. R25.1 says the freeze holds regardless of the live edge.
- Actor: Player. `context/` is silent on the buffer bound. The §7.6 alignment qualifies for 5.a (criterion 3) but is moved to 5.b by the cap. The clipping rule itself belongs in `context/` (5.c, R25). → 5.b.

**EC-5 — Annex O tests a transcription fidelity the resolution document cannot show (R13.5, R28.3).**
- Trigger: T-08 (L8548) passes only if *"The beacon set and its relative times are exactly those the decision carried"*. T-19 (L8564) counts click-tracking children against the decision.
- Why: a conformance harness needs the ADS decision as its oracle. That tests the APS-to-ADS contract that R13.5, R28.3 and §4.4 L728-730 place outside the spec.
- Actor: APS and ADS. `context/` is explicit. T-08 → 5.a, **See Actionable TODO T2**. T-19 → 5.b, because its carrier check (R28.1) has to stay and separating it from the count check is an authoring choice.

**EC-6 — UC-09's D4 counterfactual lands on the wrong option (`context/` defect).**
- `context/04-use-cases.md` L1117-1119 says that with an HTML option 2, D4 would *"have fallen to option 4"*. Option 3, an image banner, is within D4's budget, so the walk stops there. The spec gets it right (§I.5.4 L6892-6894).
- Actor: Player. The use case teaches a walk that skips a satisfiable option. → 5.c.

## Ambiguities (16)

**A-1 — Do the §4.2 / §4.4 conformance lists bind in the indicative?**
- Context: every MUST carried by R13.1, R15.2, R24 / R24.1, R28.1, R30.1, R33.4 and R6.2 (SHOULD).
- Readings: (a) the lead-ins *"A conformant Publisher:"* (L561) and *"A conformant APS returns … a document that satisfies all of the following"* (L653-655) make every bullet binding, ISO-style. (b) Under the RFC 2119 declaration at L14-16, only keywords bind, so the bullets are descriptions. §4.2 mixes "MAY" bullets into its list, which supports (a). A refined §4.4 bullet at L714 uses an explicit MUST, which supports (b). §4.5 has an explicit binding sentence (L737-739), and §4.2 / §4.4 do not.
- The spec assumed (a) implicitly and self-flags the question (Refinement gap #1, L8777). This validation scores (b), per validate-spec §4.2. Under reading (a) R6.2's SHOULD arrives stronger than `context/` (the only admitted carrier).
- Tighter sentence (spec-side convention, owner's call): *"Each item of the lists in §4.2 and §4.4 is a requirement on the conformant actor, with the force of MUST unless it states MAY or SHOULD."* → 5.b.

**A-2 — R1#p2 / R1.1 put a MUST on an actor no specification can bind.**
- Context: `03-requirements.md:121` and R1.1 (*"a Player that does not implement the new mechanisms … MUST skip them"*).
- Readings: (a) an obligation on legacy Players, which cannot be made (DR-8; spec §4.1 L549-551); (b) a property the constructs must have: removable, and ignored if unknown.
- The spec assumed (b), so the modal can never arrive.
- Tighter sentence (R1 body, R1.1): *"Every construct introduced by this proposal MUST be removable per DASH §5.2.1, such that an MPD stripped of it presents the primary content unchanged; the expected legacy-Player outcome is UC-07."* → 5.c.

**A-3 — Whom R6#p2 / R6.4 bind.**
- Context L1731-1733, L1754-1756 (Players MUST ignore unknown namespaces).
- Readings: (a) a Player that predates the spec (see A-2); (b) a conformant Player meeting an unknown foreign namespace inside the tracking subtree.
- The spec carries the behaviour only in non-normative §8.2 and as an invariant asserted in §7.9. Adding a MUST to §4.5.13 requires choosing (b). → 5.b.

**A-4 — Is a URN token a "construct" for R1.2's enumeration?**
- Context `03-requirements.md:134-147`.
- Readings: (a) a URN value in a baseline attribute is not a new construct; (b) it is one, and Table I.4's request-type URN is a fourth extension point that R1.2 does not list.
- The spec labels it as carrier "(a)" (§4.7.11 L1430), a classification its own rule does not support. → 5.b.

**A-5 — The double-box background: a composition attribute or a separate token? (R26, UC-09, UC-10)**
- Context: R26.1 L1330-1332 (*"an attribute of the slot / layout composition, NOT one of the candidate's alternative presentation options"*) against the token table L526-527, which has a separate `-background` token. UC-09 L1018 and UC-10 L1176 / L1189 use `squeezeback-double-box` for a layout that has a background.
- Readings: (a) one token, with the background an optional attribute of it; (b) two tokens that an APS may offer as ordered options.
- The spec assumed (b) (§J.1 L6976-6979, §J.3). That is why D2 in Annex J renders the background-less variant where UC-10 says D2 cannot render the side-by-side, and it lets the APS use the background as a fallback axis. The row verdicts are R26.1 `partial` and UC-10 `partial`. A reviewer applying reading (a) scores R26.1 `contradicted`, as validate-spec's worked example does.
- Tighter sentence: pick one in R26 and the token table, then align UC-09 / UC-10. → 5.c.

**A-6 — Default `@earliestResolutionTimeOffset` of 60 s against "resolved when it fires" (R36.1–R36.3).**
- Context `03-requirements.md:1078`.
- Readings: (a) an absent offset means no early resolution (`context/`); (b) an absent offset means 60 s, for parity with the linear events (spec §4.5.1 L743-745, §5.1.3 L1888, §5.1.4 L1962).
- Tighter sentence, if parity is wanted: *"a window that does not carry it takes the base specification's default for `@earliestResolutionTimeOffset`."* → 5.b.

**A-7 — R37's pause mechanism is only partly carried (R37.1–R37.3).**
- Context `03-requirements.md:1129-1137`.
- Readings: (a) any mechanism that resumes at the suspended position is a pause; (b) only `pause-fullscreen` may release resources (spec §3.4 L502).
- The resume-position rule appears only in Annex E.5.5 L5422-5424, as description. Widening the permission changes the budget tables. → 5.b.

**A-8 — Speculative pause resolution against R31.1's trigger.**
- Context: R31 body and R31.1 (a pause beginning inside the window triggers the request).
- Readings: (a) the request is caused by the pause, so fetching at the ERT is outside what R31.1 permits; (b) R31.1 only constrains which pauses a request serves.
- The spec assumed (b) (§4.5.1 L754, §6.3, §5.1.4 L1962).
- Tighter sentence (R31.1): *"The Player MAY obtain the document before the pause, provided it presents it only for a pause that begins inside the window."* → 5.c.

**A-9 — UC-05 / UC-08 D5 decline the pause ad, while R37 makes a full-screen video pause ad conformant on D5.**
- Context: `04-use-cases.md` UC-05 D5 L660-662, UC-08 D5 L977-985, coverage rows L86 / L89. UC-08 D5 also assumes the overlay window admits no `linear` fallback.
- The spec renders a `pause-fullscreen` video on D5 (§7.6, §5.3.7.3, §E.5.5, §H.5.5) and a `linear` takeover in Annex H. R37.3 supports the spec.
- Tighter sentence: rewrite both D5 rows to admit the `pause-fullscreen` video form, and the `linear` takeover when the window admits it. → 5.c.

**A-10 — "Trim clean at the previous ad boundary" needs opt-in under R4 / UC-06, yet R7.3's drop-before-play produces it.**
- Context: R4 body L328-331, UC-06 Notes L756-766, R7.3 L744-747.
- The spec treats the drop as a separate permission (§F.5, §4.5.5 L865-866).
- Tighter sentence (R4 / UC-06): *"Dropping a candidate before playback on its declared duration (R7.3) is not an overflow policy and is always admissible."* → 5.c.

**A-11 — UC-03 has the Publisher bound the number of concurrent overlays, while R22 fixes it at one.**
- The spec follows R22 (§7.4 L3521). Replace the UC-03 bullet with the R22 statement. → 5.c (low leverage).

**A-12 — Criteria whose force cannot be checked because the source has no modal.**

Suggested wording: R17.4 *"The specification MUST NOT introduce …"*; R39.2 *"… MUST list it in `@allowedLayouts`"*. → 5.c.

**A-13 — The population counts modals that bind no one (DP-2#p2–#p4).**
- The MUST / MUST NOT at `03-requirements.md:49`, :54 and :55 sit in DP-2's rationale, its counter-example and its illustrative rewrite. They can only ever be `governance`.

**A-14 — `@timescale`: fixed, or an example?**
