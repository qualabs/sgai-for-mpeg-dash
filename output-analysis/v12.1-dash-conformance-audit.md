# DASH conformance audit — v12.1 (2026-09-26)

**Audit target**: `../output/v12.1-sgai-spec.md`.
**Reference**: the edition declared in
`../context/00-normative-base.md` (ISO/IEC 23009-1:2026, Sixth edition,
2026-07). Primary copy located through `NORMATIVE_PDF_PATH`; its SHA-256
matches the declared `a7274eb2…be100`.
**Method**: inventory + clause searches against the primary copy +
per-construct verdict.

The key words MUST, SHOULD and MAY in quoted spec text are used as in
IETF RFC 2119 / RFC 8174.

## Scope

Every construct v12.1 introduces or modifies at the DASH layer: the two
window schemes and their child elements and attributes, the extension
namespace and its schema (§5.10.1), the non-linear resolution document,
the extension content of List MPDs, the empty resolution, the sub-MPD
shape, the tracking carriers, the profile usage, the `RequestParam`
rule of PUB-18, the `Metrics` declaration, and the Player rules that
bear on the semantics of inherited base constructs (execution, failure,
trimming). Design merit is out of scope.

## Method summary

- Inventory built from §1.4, §2.1, §4.2 (PUB-*), §4.5.4–§4.5.6, §4.7,
  §4.8, chapter 5 in full, §8.13, and the XML of Annexes A–Q.
- The primary copy was extracted once with `pdftotext -layout`; the
  per-page licence header/footer lines were stripped before any search,
  and the text was whitespace-flattened so that phrases spanning line
  breaks match. About 70 phrase searches were run; each quotation below
  is a verbatim hit. Zero-hit searches were controlled against a phrase
  known to be present (e.g. the Table 4 zero-duration sentence as control
  for the "zero-duration Period" search).
- The base schema fragments for `MPDtype`, `PeriodType`,
  `ImportedMpdType`, `EventStreamType`, `EventType`,
  `AlternativeMPDEventType`, `MetricsType`, `ServiceDescriptionType` and
  `PlaybackRestrictionsType` were read from the primary copy.
- Mechanical checks over the 83 XML blocks of the spec: (a) child order
  of `MPD`, `Period`, `EventStream`, `Event` against the base schema
  sequences; (b) List-profile, SPS, event-stream and SGAI co-occurrence
  rules; (c) validation of 53 standalone `svta` fragments (19
  `<svta:OverlayList>`, 20 window elements, 14 `<svta:ClickThrough>`)
  against the §5.10.1 schema with a stub `DASH-MPD.xsd` transcribing the
  base `EventStreamType` / `EventType`. Result: 0 findings, except the
  two expected ones (G.3 is the document *after* namespace removal; the
  §5.3.5 and §5.5.2 snippets are local elements shown out of context).
  Each check was first run against a deliberately broken input and
  reported every planted defect.
- Each construct assessed Conforming / Marginal / Non-conforming.

## Base-standard findings (highlights)

- **Extension points.** `MPD`, `Period`, `EventStream`, `Event` and
  `AlternativeMPDEventType` carry `xs:any ##other`; `EventStream` has no
  `xs:anyAttribute`; `ImportedMpdType` is simple content with foreign
  attributes only. DR-2 of §4.7.1 is accurate.
- **Events.** DASH §5.10.2.1 explicitly admits scheme-specific child
  elements *"in some external namespace"*, fixes one stream per
  scheme/value, and terminates events at the Period end.
- **List / SPS.** The List profile is an extension of the CMAF profile
  and requires `type="list"` plus its URN; §8.1 conditions *Media
  Presentation* conformance on *"at least one Representation in each
  Period in the profile-specific MPD for ProfA"*. Every step number of
  the Linked Period merge cited by the spec (1 c, 3 a i, 3 b iv, 3 b ix,
  3 c iv, 3 d iii) is correct.
- **Advanced Linear.** Its only event rules name Alternative MPD,
  Callback and MPD Validity Expiration; the base's own Annex K.6.4 example
  (profile `urn:mpeg:dash:profile:advanced-linear:2025`) carries a
  `urn:mpeg:dash:event:service-description:2024` stream, which §8.13.2.2
  does not name — as §8.13 item 1 of the spec says.

## Marginal items detail

### K-4 — Unregistered URN namespace `svta`

- **Ambiguity.** The base accepts any URN (*"may be a URN or a URL"*,
  DASH §5.10.2.1), but a URN with an unregistered NID is not a valid URN
  under RFC 8141, so "URN" is satisfied only syntactically. The claim of
  non-registration is the spec's own (§8.13 item 13); this audit did not
  consult the IANA registry.
- **Suggested clarification.** Either obtain the NID (or use a URL-form
  scheme identifier under a domain SVTA controls), or state in §2.1 that
  the identifiers are opaque URIs whose uniqueness SVTA guarantees.

### K-10 — `@executeOnce` on the pause window

- **Base text.** *"specifies whether the event is executed only once
  during the media presentation. If true, if some of the media during the
  active interval of this event is played more than once, the event is
  executed only the first time this media time is traversed."* (Table 63)
- **Spec text.** *"the window yields at most one pause ad for the whole
  session … The name is the base's, and so is the counter rule"* (§5.1.4).
- **Ambiguity.** The base bound is about re-traversal of media time within
  one media presentation; the spec's bound blocks a second pause in the
  same traversal (E.10: second pause at 50:00 shows nothing) and uses
  "session", which the base does not define. The name is reused with
  semantics that are close but not identical, against the spec's own
  claim of reuse "with all its characteristics" (DOC-40, §4.8.2).
- **Suggested clarification.** Replace "session" with "media
  presentation", and state that the execution counted is a pause ad that
  starts rendering, which is this specification's mapping of E.c; or mint
  a distinct name.

### K-17 — Empty linear resolution

- **Base text.** Table 4: *"At least one Adaptation Set shall be present in
  each Period unless the value of the @duration attribute of the Period is
  set to zero."* DASH §8.1: *"A Media Presentation is conforming to
  profile ProfA when … There is at least one Representation in each Period
  in the profile-specific MPD for ProfA."* DASH §8.14 rule 2 obliges the
  List URN in `@profiles`. DASH §5.16.2.2.6 lists failures including
  *"The playback of the alternative presentation cannot start"* and
  *"Alternative MPD is a List MPD, and merge process resulted in no
  available media"*.
- **Ambiguity.** The document is a valid MPD but cannot be a conforming
  Media Presentation of the profile it must declare. With no
  `ImportedMPD`, no merge happens, so the second failure reason does not
  literally apply; a base Player could treat a zero-length presentation as
  one that *started*, increment E.c, and consume an `@executeOnce` event,
  which is the opposite of PLY-44. The spec acknowledges the first point
  (§8.13 item 10) and relies on the first failure condition.
- **Suggested clarification.** Keep the shape but record in §8.13 that a
  base Player may count it as an execution, or submit the question to the
  base editors (a zero-duration List MPD as the canonical "no ad" answer).

### K-20 — SGAI event streams under Advanced Linear

- **Base text.** DASH §8.13.2.1: *"Periods and Representations which do not
  conform to the constraints in this subclause may not be presented."*
  DASH §8.13.2.2: *"EventStream elements may indicate Alternative MPD (5.16)
  and Callback (5.10.4.5) event schemes."*
- **Ambiguity.** If the list is exhaustive, a Period carrying an SGAI
  stream is non-conforming and "may not be presented" — the main content
  itself. The base's own Annex K.6.4 example carries an unlisted scheme,
  which argues against exhaustive reading. PUB-18 routes Publishers using
  `RequestParam` to this profile, so the question is live.
- **Suggested clarification.** Already recorded as open (§8.13 item 1).
  Until answered, PUB-18 could note that an Advanced Linear MPD carrying
  SGAI windows relies on the non-exhaustive reading.

### K-22 — `<svta:Tracking>` reuses `EventStreamType` with altered semantics

- **Base text.** Table 44, `@id`: *"Each EventStream element shall not
  contain two Event elements with the same value of Event@id"* and *"The
  scope of the @id for each Event is within the same @schemeIdURI and
  @value pair over the duration of the current media presentation"*;
  `@presentationTime` is relative to the Period start.
- **Ambiguity.** The element is not an `EventStream` and sits in a
  non-MPD document, so no base rule is violated, and the base schema has
  no identity constraint a validator would enforce. But the spec reuses the
  type "whole" while declaring three of its semantics its own: timebase
  (candidate start), `@id` scope (one candidate, one presentation) and
  permitted repeated `@id` — the last overriding a base *"shall not"*.
  The type also admits children and attributes the carrier gives no
  meaning (`BaseURL`, `RequestParam`, descriptors, `xlink:*`). An
  implementer reusing a base event parser inherits the base semantics by
  default.
- **Suggested clarification.** Drop the repeated-`@id` permission (the
  base rule costs nothing inside one `<svta:Ad>`, and the URL/time
  de-duplication already covers duplicates), and state that the other
  children and attributes of the type are ignored on this carrier.

### K-30 — PLY-35 drop-before-play on List MPD candidates

- **Base text.** Table 57: *"For insertion events, APDA = min(APD,
  APDmax)."* The model is normative for authors: *"the MPD author may
  assume that the steps described in this subclause are taken"* (DASH
  §5.16.2.2.1).
- **Ambiguity.** On an inherited event, a Player of this specification
  may skip a whole Period the base would play and then trim. §4.8.3
  states that "one decision departs" (PLY-48); this is a second behaviour
  on a base construct not listed there. The spec flags it (§4.5.5, §8.13
  item 12) without deciding.
- **Suggested clarification.** Either restrict PLY-35 to the non-linear
  families, or list it in §4.8.3 as a declared departure with its scope.

### K-31 — PLY-41: a List MPD whose candidates cannot render

- **Base text.** DASH §5.16.2.2.6: failure when *"The playback of the
  alternative presentation cannot start. The reasons for this include (but
  are not limited to) …"*; §5.16.2.2.5 step 2 d: *"If execution fails,
  steps a-c above are repeated for next events in QE"*.
- **Ambiguity.** A List MPD none of whose candidates the device can play
  is a natural instance of "cannot start". PLY-41 declares it not a
  failure, which suppresses the base fall-through to the next event. Not
  listed in §4.8.3; flagged in §8.13 item 12.
- **Suggested clarification.** Limit PLY-41 to the non-linear families
  (where it is this specification's own rule), or record the linear case
  as a declared departure.

## Open questions surfaced

No `[fetch-failed]` item: every governing clause was located and quoted.
Questions the base text leaves open, all already carried by §8.13:

- Exhaustiveness of the Advanced Linear event list (K-20; §8.13 item 1).
- Whether an empty List MPD is a failed execution for a base Player
  (K-17; §8.13 item 10).
- Whether PLY-35 / PLY-41 are departures (K-30, K-31; §8.13 item 12).
- NID registration of `svta` — not checked against the IANA registry
  (K-4; §8.13 item 13).
