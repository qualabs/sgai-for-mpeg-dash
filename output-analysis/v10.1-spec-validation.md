## Gaps (3)

### G-1 — Request-level extension hooks are not among the admissible extension points

- **Spec**: §4.7.5 L1289-1308 and §4.7.6 L1320-1321 carry a request-type URN
  in `RequestParam@includeInRequests`, relying on the DASH Table I.4 drop rule.
  They also carry reserved query parameters, which R29 itself requires.
- **Missing in `context/`**: R1.2 and DR-1..DR-10 of `08-dash-extension-rules.md`
  enumerate MPD-level hooks only (foreign namespace, event streams,
  descriptors). `grep -n -i "includeInRequests\|query param" context/08-dash-extension-rules.md`
  returns nothing. Neither file admits or forbids a token in a base attribute
  value, or a query parameter.
- **Implementer today**: follows the spec's argument that the drop rule makes
  the URN safe. Nothing in `context/` confirms it. Routed 5.c.
- **Routing**: See Deferred d-16.

### G-2 — `context/05` and the spec describe different base constructs for URL parameters

- **Spec**: §5.8.1 L2812-2822 uses `<RequestParam>` of `ExtendedUrlInfoType`
  (DASH §I.3.1). It quotes the base as saying the MPD-level `EssentialProperty`
  *"shall be present and have no content"*.
- **`context/`**: `05-dash-linear-interfaces.md` L123-125, L176-195 and L261-266
  describe a `UrlParamInfo` descriptor (§I.4) in the namespace
  `urn:mpeg:dash:schema:urlparam:2025`, nested **inside** that
  `EssentialProperty`.
- **Why it matters**: if the spec's quotation is right, the context example
  puts content in an element the base requires to be empty. This step cannot
  tell which reading of the base is right `[inferred]`. A reader of `context/`
  alone authors something the spec does not describe. Routed 5.c.
- **Routing**: See Deferred d-6.

### G-3 — Points the spec declares open are not recorded as open in `context/`

- **Spec**: §8.13 L3788-3815 lists points *"the edition defines no answer"*
  for. Among them: audio during a non-linear form (L3802), per-option
  tracking and ClickThrough (L3810), signalling support for `custom`, and a
  hybrid break over an insertion.
- **`context/`**: its "Deliberately open" table (03-requirements.md L2182-2189)
  is empty, and it says an empty table means *"no silence in this
  specification has been declared deliberate yet"*.
  `grep -n -i "per-option\|different durations" context/*.md` returns nothing.
  `grep -n -i audio context/*.md` returns only RFC 4337 media types and UC-14's
  slate. So the spec declares open questions that `context/` never opened. For
  audio, an implementer of a video overlay has to guess whose audio plays.
  With per-option schedules, a 10 s image option inherits a 15 s video
  option's quartiles.
- **Implementer today**: guesses. Routed 5.c.
- **Routing**: See Deferred d-7.

## Edge cases (4)

### EC-1 — A blackout replacement with no `@maxDuration` is skipped

- **Trigger**: a UC-14-shape `ReplacePresentation` blackout that omits
  `@maxDuration`.
- **Why it matters**: §4.5.1 item 7 L811-814 (*"MUST present no ad in a window
  whose `@maxDuration` is absent"*) and §4.8.3 L1375 (*"including an inherited
  linear event"*) apply, because a Player cannot tell a slate from an ad
  (§4.2 item 2 L660). The programme that should be blacked out plays. §4.2
  item 2 now makes the omission non-conformant authoring. But §4.8.3's reason
  (*"A Publisher who omits the cap notices at once — nothing sells"*) does not
  hold for a replacement that is not an ad: the failure is a rights breach and
  not a missed sale.
- **Actor**: Publisher, Player. `context/` is silent: R4.10 speaks only of
  *"ads from such a slot"*. Routed 5.c.
- **Routing**: See Deferred d-8.

### EC-2 — A `linear` takeover offered on an overlay window of live content

- **Trigger**: an overlay window in a `type="dynamic"` MPD admits `linear`,
  and a candidate offers the takeover.
- **Why it matters**: §5.3.3 L2362-2369 says the takeover suspends the primary
  content and resumes it *"from where it was suspended, as with an
  insertion"*. §5.1.1 L1568-1571 excludes insertion on live content, *"because
  a timeline that can be stopped for an indefinite period is an on-demand or
  pre-recorded one"*. On live content the takeover pushes the viewer behind
  the live edge, and the spec does not say what happens at the resume (the
  time-shift rule of §8.8 is written for pauses).
  `grep -n -i takeover` over the spec and `context/` finds no live or dynamic
  mention.
- **Actor**: Player, Publisher. `context/` is silent (R12 introduces the
  takeover as a fallback option without a timeline model). Routed 5.c.
- **Routing**: See Deferred d-9.

### EC-3 — `@dismissAfter` on a pause slot is measured on a timeline that is frozen

- **Trigger**: a pause document with `@dismissAfter="PT5S"` and an image pause
  ad.
- **Why it matters**: §4.5.14 item 1 L1075-1079 and §5.2.4 L2125 measure the
  delay *"on the presentation timeline"*. During a pause the primary
  presentation timeline does not advance (§4.5.4 item 5), and an image has no
  media timeline. Read one way, the ad never becomes dismissible. Read the
  other way, the clock is the ad's own presentation, as §5.5.3 L2702-2704 does
  for image beacons. §4.5.14 item 6 makes dismissal apply to the pause family.
- **Actor**: Player. R35.2 says only *"from the moment the slot begins
  rendering"*, with no timeline, so the spec added the timeline and the
  ambiguity with it. Routed 5.b.
- **Routing**: See Flagged f-6.

### EC-4 — A per-ad base skip inside a linear slot

- **Trigger**: a List MPD Period carries `PlaybackRestrictions@skipAfter`.
- **Why it matters**: §5.2.4 L2168-2178 lets the viewer skip that one ad and
  continue the slot, on the ground that a per-ad skip is not a dismissal. R35
  says the unit of dismissal is the slot, *"never an individual ad inside
  it"*, and R35.4 forbids advancing after a dismissal. `context/` does not
  draw the skip/dismissal distinction the spec relies on.
- **Actor**: Player. Routed 5.c.
- **Routing**: See Deferred d-15.
