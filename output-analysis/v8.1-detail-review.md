## The defect class this pass found

The refinement inserted its 66 audit annotations as HTML comments on their own
line. In CommonMark an HTML comment at the start of a line is a block-level
construct that **interrupts** whatever block it lands in, so 19 of the 66
changed how the document renders, and one more pointed at the wrong passage:

| Effect | Sites |
|---|---|
| A `**bold**` span split in two — the `**` markers render **literally** | 2 |
| A paragraph split into two paragraphs | 15 |
| A blockquote split into two blockquotes | 1 |
| A bullet list split into two lists | 1 |
| Anchored to a passage the refinement did not edit | 1 |

This is measurable end to end. Rendering the candidate as received produced
**4 literal `**` sequences**, 658 `<p>`, 10 `<blockquote>`, 16 `<ul>` and 570
`<strong>`; rendering it after the fixes produces **0 literal `**`**, 640 `<p>`,
9 `<blockquote>`, 15 `<ul>` and 572 `<strong>` — the same structure v8 renders,
plus exactly the four paragraphs, one table and one `<strong>` v8.1 legitimately
adds.

The placement rule applied is the one the five table annotations already follow:
**an annotation sits immediately above the block it annotates**, never inside
it. The single list annotation is the exception, indented by two spaces instead
of moved: indenting keeps it adjacent to the bullet it marks *and* keeps the
list intact, which moving it above the list would not.

A second, independent artefact of the same cause: nine paragraphs were edited
without being rewrapped, leaving two lines over the document's 75-column prose
convention and seven orphan fragments mid-paragraph (`in`, `§5.3.2.`,
`sequence. Each`). Mid-paragraph lines under 40 columns went from 5 in v8 to 12
in v8.1, all seven of the new ones inside refined passages. Those nine
paragraphs were rewrapped.

## Where v8's two flags stand

**F1 — the category segment in the minted URIs. The spec side is closed.** v8
flagged that `context/06-naming-and-namespaces.md` states the pattern
`urn:svta:dash:<construct>:<year>` and illustrates it with
`urn:svta:dash:sgai-overlay:2026`, showing no category segment, while the spec
mints four URIs that carry one. v8.1 adds the reading to §2.1 (L178-186):
`<construct>` is a multi-segment path whose first segment names the category,
mirroring the baseline's own `urn:mpeg:dash:event:callback:2015` and
`urn:mpeg:dash:profile:list:2024`. That is resolution (a) of the two v8
recommended, and it does what it was asked to do: a reader auditing §2.1 against
`context/06` now finds the divergence declared instead of an apparent `MUST`
violation. Both baseline URIs the new sentence cites are the ones the spec
already uses at L195 and L196, so the citation is internally consistent.

The residual is entirely on the `context/` side — the pattern there still does
not show the segment — which is resolution (b), a `context/` edit a minor
refinement cannot make, and it is recorded as `Refinement gaps` #20. **No
spec-side flag remains for F1.** What the new sentence did introduce is flagged
issue 2 above: it over-reaches by one table row.

**F2 — XML example prologue conventions. Unchanged, and still open.** Flagged
issue 3 above carries it, with the counts re-measured on this candidate rather
than copied from v8's log. The refinement deferred it deliberately
(`Refinement gaps` #19) and touched no example, so nothing about it moved.

## Open questions surfaced

- **Annex O still carries no `*Informative.*` marker** where A-N all do. This is
  v8's open question and nothing in v8.1 touched it. It remains not an omission
  of meaning — the annex's opening paragraph says *"It is informative"* in prose
  — but a reader scanning for the marker will not find one, and adding it to an
  annex titled *Test cases and conformance criteria* is a statement about
  normative status rather than a formatting fix.
- **Nothing in `bin/` checks annotation placement**, and the class this pass
  found is one a refinement will reproduce every time it runs: the refine step
  inserts a line-initial HTML comment above the line it edited, which is correct
  only when that line starts a block. A check that renders the candidate and
  compares its block counts against the spec it was refined from would catch the
  whole class at the point it is introduced rather than one step later.
